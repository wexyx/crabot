# 附件与上下文

## 文件和图片

Web 的项目、管理和 Agent 测试聊天可以添加文件、拖入文件或粘贴图片。上传完成后再发送；附件会显示文件名，点击图片放大预览，文件通过下载链接保存。

CLI 使用 `/attach /path/to/file`，随后发送分析问题；`/detach` 清空待发送附件，不删除文件。相对路径以启动目录为准，路径包含空格时可加引号。通过 SSH 运行 CLI 时，这是远端机器的路径；电脑上的文件需先用 scp/SFTP 传到远端，或通过 Web 上传。

- CLI 引用原文件，不复制整个目录；仅支持普通文件。
- Web 上传保存在当前实例的 `tmp/attachments` 目录，返回受管理接口保护的附件链接。重启后仍可读取，不自动清理已经引用的附件；删除该目录下的附件会使对应历史链接失效。
- 上传文件在执行时复制到工作目录 `.crabot/tmp/`（命名实例为 `.crabot_<别名>/tmp/`），本次执行结束后清理副本；实例数据目录中的原件继续用于历史会话。
- 单文件最多 10 MiB，图片最多 5 MiB；一次上下文最多 8 个附件、总计 20 MiB。索引记录链接，不嵌入 Base64。
- UTF-8 文本提供首段内容及文件路径，剩余内容可由工具读取；PDF、Office 等二进制文件需要 Agent 使用适当的解析工具，不会伪装成已经提取文本。
- PNG/JPEG/GIF/WebP 图片使用模型原生图片输入。Crabot 支持 Chat、Responses、Anthropic 协议；Codex 使用图片参数，Claude 使用结构化输入。需要对应模型支持视觉；Mock 只用于验证流程，不会识图。
- 选中并发送附件意味着允许当前会话读取该文件，并交给所选模型分析；不会因此开放整个目录。命令执行仍遵循权限策略。

附件只属于当前 Crabot 实例。本次未增加跨 Crabot 的附件自动转发；组网中的远端 Agent 无法解析另一实例的本地附件 ID。远端 Web 可沿用 SSH 端口转发访问，不改变原来的本机管理访问限制。

## 按需上下文

Crabot 不再默认设置 4096 的回复输出上限。Agent 的“最大输出长度”留空时，Chat / Responses 请求不发送输出限制，由模型服务使用其默认值；填写 `HARNESS_MAX_TOKENS` 时才发送指定的正整数上限。已有配置中显式填写的值仍有效，清空即可恢复自动模式。

Anthropic Messages 必须携带 `max_tokens`，自动模式通过模型信息接口获取其上限，并在当前运行器内缓存；兼容服务不支持该接口时，会提示手动填写，不猜测一个固定值。上下文容量与模型自身的输出上限依然存在；本地自动上下文计算预留四分之一容量，但不会把这个预留值作为回复长度限制发送。

聊天记录只写入本项目知识索引（无 JSONL 日志文件）。每个 Agent 的上下文为它自己的最后一次摘要，加上该摘要覆盖序号之后的全部对话记录；没有摘要时读取重置点之后的记录，不再按固定轮数截断。每条记录的完整事件（含工具输入输出）在索引中保留，供 Web/CLI 展示与 `find(target=history)` 按相关性取回。

`compact` 通过 `find(target=tool, query=compact)` 解锁，只做上下文管理（触发压缩或丢弃旧轮次）：

- `{"strategy":"summary"}`（默认）：触发宿主驱动压缩——宿主把当前上下文窗口交给模型生成摘要，写入摘要索引（按 `(chat, agent)` 隔离，不同 Agent 的上下文长度上限不同，摘要各自独立），并把窗口压缩为该摘要；下次启动同一聊天时，上下文窗口优先读取最后一次摘要，再读摘要之后的原始记录。
- `{"strategy":"recent"}`：不生成摘要，仅保留任务和最新完整工具轮次，旧细节用 `find` 回查。

压缩在当前工具轮次结束后生效，不删除任何记录：被摘要覆盖的记录仍在索引中，`find(target=history)` 可按相关性取回。摘要与历史索引均为内部使用，不会主动暴露给模型。该工具适用于 Crabot，以及通过工具桥接接入的 Claude/Codex，不会声称修改外部 CLI 的内部模型缓存。

摘要索引与聊天历史索引同属一个知识索引；Web/CLI 展示、上下文窗口构建都从索引读取。旧版本的聊天日志文件不再读写，也不自动导入。界面仍展示完整原始聊天；一个 Agent 的压缩不会隐藏其他 Agent 的历史。摘要仅覆盖本次实际读取的快照，新到达的消息不会被误算进覆盖范围。

工具执行进度在 Web 和 CLI 中使用单行状态；Web 点击展开详情，CLI 使用 `/tools [序号]`。权限确认仍单独展示，不会被轮播隐藏。
# 浏览器与执行时长

内置 `browser-automation` Skill 默认使用 Puppeteer；在 Skill 目录运行 `node install.mjs`，依赖和匹配的 Chrome Headless Shell 安装到 `<实例数据目录>/runtime/browser-automation/.runtime/`。该目录跨版本复用；原生工具与 Skill 共用它，缺失时按执行授权自动构建。目标机器需安装 Node.js/npm。浏览器使用临时独立配置，不复用个人 Chrome 数据。

浏览器通过 `browser-automation` Skill 的 Puppeteer 脚本读取网页和截图，由 `shell` 执行；展示图片使用 `image-view` Skill。Crabot 不再套外层系统沙箱，Chromium 自身沙箱仍保留。普通命令、Python 和 Skill 同样直接在本机执行，仍受操作确认和启用策略控制。

Agent、群聊和 A2A 任务不再设置固定 600 秒总执行时长。主动停止、单次模型请求超时和单条工具命令的超时仍保留。

## 在聊天中展示生成的图片

Agent 加载 `image-view` Skill，通过 `shell` 执行 `show.py 图片路径`。脚本调用当前命令期间有效的本地内部服务，返回可用于 Web 展示的引用。只接受当前工作目录对应实例 tmp 下的本地 PNG/JPEG/GIF/WebP 图片，最大 5 MiB；不接收 URL，不抓取网络资源，拒绝目录穿越和指向 tmp 外的符号链接。浏览器截图完成后也使用此 Skill 发布。

工具返回 preview_url 和 reference；Agent 原样引用 reference，Web 即显示缩略图，点击可放大，另有下载链接。这是给用户展示图片，并不意味着模型已分析图片内容。

服务器保存一份不可变附件快照，使用已有附件 ID 接口提供内容，不开放任意路径下载接口。预览链接为相对路径，Web 自动使用当前连接的 Crabot 地址，无需配置公开 host。自定义域名通过反向代理访问 Web 即可；链接仍受原有访问控制，不是匿名公网分享链接。

这些文件不再写到工作目录根部。已有旧截图不自动移动或删除，避免破坏历史引用。
