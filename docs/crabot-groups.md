# 群策略与 A2A

群管理支持 AdminAgent 管理工具，以及 Web 的「群配置」面板；不再暴露旧 /v1/crabot/control。
群聊消息与历史属于基础交互通道，见 [AdminAgent 接口](admin-agent.md)。

Policy 包含 mode（pmo / a2a / relay）、members（后代 path + role）、leader、rounds、instructions、relay_strategy。
一个群最多 8 名成员、最多 60 轮，不允许同时选择某棵子树及其后代。Leader 模式 的 leader 必须是群成员。
Leader 模式 按角色分工并汇总；讨论模式按顺序判断职责，无关成员让出；有结论且其他成员确认或让出后结束，全部让出则提示无人认领；新意见会重置确认，轮次仅为上限；Relay 仅在 token / 额度 / 上下文限制错误时切换，其他失败停止。

Relay 的 `relay_strategy` 支持：

- `manual`（默认，兼容旧配置）：按照 members 的顺序。Web「群配置 → 成员与角色」上移/下移调整优先级。
- `random`：每次任务开始时随机排列，本次接力期间顺序固定。
- `negotiated`：逐个询问成员接手意愿（0–100）和理由，后续成员可看到之前的有效回应。按分数降序执行，平分保留手动顺序；每位协商最多等待 15 秒，超时、报错或无效回应随机分配 0–100 分，标记随机补位。这是自评分协商，不是多数投票。额外调用每个成员一次，嵌套子群可能产生更多模型调用。

在「群配置 → 协作策略」选择接力顺序。实际顺序、协商摘要和 Token 不足切换会写入聊天。修改使用 expected_version 检查，只影响后续任务。协商提示要求成员不要执行任务或工具，但不额外改变成员的工具权限。

B 提供默认模板。A 创建 G 时复制成 B@G，之后 A/B 编辑同一权威副本；其他群和默认模板不受影响。
AdminAgent 修改策略前需读取版本，工具执行 expected_version 乐观检查，冲突要求重新读取，不静默覆盖。
执行前冻结远程成员策略，运行中编辑影响后续执行，不影响当前快照。

创建遇到离线成员会留下 draft，恢复后通过 group_provision 工具重试。更深层子群在执行冻结时按需创建。
父节点只能访问后代，不能向上或横向访问。远程子群目前返回完整结果，不逐 token 透传。
执行历史保留，但不保证跨节点取消、Exactly-once 或自动恢复未完成任务。
