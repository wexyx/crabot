# Crabot 架构

核心架构与数据流统一维护在 [README · 助手们怎样一起工作](../README.md#助手们怎样一起工作)，避免多份说明随实现演进产生冲突。

## 节点内的职责划分

```text
crates/agent-node/src/
  app/          启动配置、实例选择、组件装配与关闭
  cli/          终端输入、展示、导航与人工确认
  http/         Web 静态资源、HTTP 请求与 SSE 适配
  management/   管理会话与管理能力集
  core/         Agent、项目、任务、会话、策略与权限
  a2a/          注册、挂载、下行 RPC 与连接身份
  storage/      状态事务 JSONL、聊天知识索引与恢复
```

CLI 和 HTTP 调用同一应用层，既不通过对方转发操作，也不独立维护另一份业务状态。Core 和 A2A 目前仍位于同一个 crate，不是单独部署的服务。

Provider 工厂与生命周期在 `agent-runtime`。Mock、Crabot、Codex、Claude 是平级运行器，厂商配置和输出解析封装在各自模块内。模块门面只声明模块和导出，不放业务逻辑。

## 一致性与边界

实例锁阻止同目录多进程写入；状态事务提交为一行 JSONL，失败回滚内存修改。项目策略的版本校验和更新在同一个事务中完成。聊天事件直接写入按项目隔离的知识索引（LadybugDB），不整份聊天重写。

每个节点独立保存数据，A2A 挂载不是共享文件系统，也不是跨节点全局事务。连接使用 AK/SK，节点只能按授权访问后代子树，远端 Agent 定义仍由远端维护。Web 管理入口只允许本机回环访问，不使用 AdminToken。

多用户使用独立进程和数据目录。文件沙箱控制执行范围，工具启用状态与人工授权是独立层次。完整配置及限制见 [使用与配置](usage.md)。
